Crea un servidor MCP para usarlo con aplicaciones ChatGPT, investigaciones exhaustivas o integraciones de API.

El Protocolo de Contexto de Modelos (MCP) es un protocolo abierto que se está convirtiendo en el estándar de la industria para ampliar los modelos de IA con herramientas y conocimientos adicionales. Los servidores MCP remotos se pueden usar para conectar modelos a través de Internet con nuevas fuentes de datos y capacidades.

En esta guía, explicaremos cómo crear un servidor MCP remoto que lea datos de una fuente de datos privada (un almacén de vectores ) y los ponga a disposición en ChatGPT como una aplicación solo de datos (anteriormente llamada conector) para chat, investigación profunda y conocimiento de la empresa, así como a través de una API .

Nota : Para configurar la aplicación ChatGPT (modo desarrollador, conexión con el servidor MCP e interfaz de usuario opcional), consulte la documentación del SDK de aplicaciones: Inicio rápido , Configuración del servidor MCP , Conexión desde ChatGPT y Autenticación . Si está creando una aplicación que solo maneja datos, puede omitir los recursos de la interfaz de usuario y exponer únicamente las herramientas.

Actualización de terminología : A partir del 17 de diciembre de 2025 , ChatGPT cambió el nombre de los conectores a aplicaciones. La funcionalidad existente se mantiene, pero la documentación y la interfaz de usuario del producto siguen utilizando el término «aplicaciones». Consulte las actualizaciones del Centro de ayuda: Aplicaciones de ChatGPT con sincronización , Información de la empresa en ChatGPT y Controles de administración, seguridad y cumplimiento en las aplicaciones .

Crear un servidor MCP

A continuación, vamos a crear un servidor MCP remoto que realizará búsquedas en nuestro almacén de vectores y podrá devolver el contenido de los documentos para los archivos con un ID determinado.

En este ejemplo, vamos a construir nuestro servidor MCP usando Python y FastMCP . Al final de esta sección, se proporcionará una implementación completa del servidor, junto con instrucciones para ejecutarlo en Replit .

Tenga en cuenta que existen otros marcos de servidor MCP que puede utilizar en diversos lenguajes de programación. Sin embargo, independientemente del marco que utilice, las definiciones de herramientas en su servidor deberán ajustarse a la estructura descrita aquí.

Para trabajar con la investigación profunda de ChatGPT y el conocimiento de la empresa (y la investigación profunda a través de la API), su servidor MCP debe implementar dos herramientas de solo lectura: searchy fetch, utilizando el esquema de compatibilidad en Compatibilidad del conocimiento de la empresa .

Declare un esquema de salida para cada herramienta para que los clientes puedan validar la estructura del resultado. En FastMCP, los modelos de retorno tipados pueden generar este esquema automáticamente; el ejemplo siguiente lo pasa output_schemaexplícitamente desde esos mismos modelos.

searchherramienta

Esta searchherramienta se encarga de devolver una lista de resultados de búsqueda relevantes de la fuente de datos de su servidor MCP, en función de la consulta del usuario.

Argumentos:

Una única cadena de consulta.

Devoluciones:

Un objeto con una sola clave, results, cuyo valor es una matriz de objetos de resultado. Cada objeto de resultado debe incluir:

id- un identificador único para el documento o el elemento de resultado de la búsqueda
title- Título legible para humanos.
url- URL canónica para citar.
En MCP, devuelva este objeto como structuredContente incluya el mismo valor como una cadena codificada en JSON en la matriz de contenido para compatibilidad.

La respuesta final de la herramienta debería tener este aspecto:

{
  "structuredContent": {
    "results": [{ "id": "doc-1", "title": "...", "url": "..." }]
  },
  "content": [
    {
      "type": "text",
      "text": "{\"results\":[{\"id\":\"doc-1\",\"title\":\"...\",\"url\":\"...\"}]}"
    }
  ]
}
fetchherramienta

La herramienta de recuperación se utiliza para obtener el contenido completo de un documento o elemento resultante de una búsqueda.

Argumentos:

Una cadena de caracteres que actúa como identificador único del documento de búsqueda.

Devoluciones:

Un único objeto con las siguientes propiedades:

id- un identificador único para el documento o el elemento de resultado de la búsqueda
title- un título de cadena para el elemento del resultado de la búsqueda
text- El texto completo del documento o elemento
url- Una URL que enlaza con el documento o el resultado de la búsqueda. Útil para citar recursos específicos en la investigación.
metadata- un par clave/valor opcional de datos sobre el resultado
En MCP, devuelva este objeto como structuredContente incluya el mismo valor como una cadena codificada en JSON en el array de contenido para compatibilidad.

La respuesta final de la herramienta debería tener este aspecto:

{
  "structuredContent": {
    "id": "doc-1",
    "title": "...",
    "text": "full text...",
    "url": "https://example.com/doc",
    "metadata": { "source": "vector_store" }
  },
  "content": [
    {
      "type": "text",
      "text": "{\"id\":\"doc-1\",\"title\":\"...\",\"text\":\"full text...\",\"url\":\"https://example.com/doc\",\"metadata\":{\"source\":\"vector_store\"}}"
    }
  ]
}

Gestionar la autenticación

Como desarrollador de un servidor MCP remoto personalizado, la autorización y la autenticación le ayudan a proteger sus datos. Recomendamos usar OAuth con documentos de metadatos de ID de cliente para el registro de clientes cuando su servidor de autorización admita CIMD y el creador del conector lo elija. ChatGPT admite CIMD con intercambio de tokens de cliente público ( none) o intercambio de tokens de aserción de cliente firmado ( private_key_jwt). El registro dinámico de clientes sigue siendo compatible cuando está configurado. Para conocer los requisitos de autenticación de la aplicación ChatGPT, consulte Autenticación . Para obtener detalles del protocolo, lea la guía del usuario de MCP o la especificación de autorización .

Si conectas tu servidor MCP remoto personalizado en ChatGPT como una aplicación, los usuarios de tu espacio de trabajo recibirán un flujo OAuth para tu aplicación.

Riesgos y seguridad

Los servidores MCP personalizados permiten conectar tu espacio de trabajo de ChatGPT con aplicaciones externas, lo que posibilita que ChatGPT acceda, envíe y reciba datos en dichas aplicaciones. Ten en cuenta que los servidores MCP personalizados no son desarrollados ni verificados por OpenAI, sino que son servicios de terceros sujetos a sus propios términos y condiciones.

Si encuentra un servidor MCP malicioso, infórmelo a security@openai.com .

Riesgos relacionados con la inyección inmediata

Las inyecciones de mensajes son un tipo de ataque en el que un atacante inserta instrucciones maliciosas en contenido que uno de nuestros modelos probablemente encontrará (como una página web), con la intención de que dichas instrucciones anulen el comportamiento previsto de ChatGPT. Si el modelo obedece las instrucciones inyectadas, puede realizar acciones que el usuario y el desarrollador jamás pretendieron, incluyendo el envío de datos privados a un destino externo.

Por ejemplo, podrías pedirle a ChatGPT que busque un restaurante para una cena en grupo consultando tu calendario y tus correos electrónicos recientes. Durante la búsqueda, podría encontrar un comentario malicioso (esencialmente, un contenido dañino diseñado para engañar al agente y que realice acciones no deseadas), que le ordene obtener un código de restablecimiento de contraseña de Gmail y enviarlo a un sitio web malicioso.

Riesgos relacionados con la inyección tardía

Existen riesgos adicionales asociados a los MCP personalizados, no relacionados con los ataques de inyección rápida:

Las acciones de escritura pueden aumentar tanto la utilidad como los riesgos de los servidores MCP , ya que permiten que el servidor realice acciones potencialmente destructivas en lugar de simplemente enviar información a ChatGPT. Actualmente, ChatGPT requiere confirmación manual en cualquier conversación antes de que se puedan realizar acciones de escritura. La confirmación marcará los datos potencialmente confidenciales, pero solo debe usar acciones de escritura en situaciones en las que haya considerado cuidadosamente y esté conforme con la posibilidad de que ChatGPT pueda cometer un error relacionado con dicha acción. Es posible que se produzcan acciones de escritura incluso si el servidor MCP las ha marcado como de solo lectura, por lo que es aún más importante que confíe en el servidor MCP personalizado antes de implementarlo en ChatGPT.
Cualquier servidor MCP puede recibir datos confidenciales durante las consultas . Incluso si el servidor no es malicioso, tendrá acceso a los datos que ChatGPT proporcione durante la interacción, incluyendo potencialmente datos confidenciales que el usuario haya facilitado previamente a ChatGPT. Por ejemplo, estos datos podrían incluirse en las consultas que ChatGPT envía al servidor MCP al utilizar herramientas de búsqueda avanzada o aplicaciones de chat.
Conectando con servidores de confianza

Le recomendamos que no se conecte a un servidor MCP personalizado a menos que conozca y confíe en la aplicación subyacente.

Por ejemplo, siempre elija servidores oficiales alojados por los propios proveedores de servicios (p. ej., conéctese al servidor Stripe alojado por Stripe en mcp.stripe.com, en lugar de un servidor MCP no oficial de Stripe alojado por un tercero). Dado que actualmente no existen muchos servidores MCP oficiales, podría verse tentado a usar un servidor MCP alojado por una organización que no lo opera y simplemente actúa como proxy para las solicitudes a ese servicio a través de una API. Esto no es recomendable, y solo debe conectarse a un MCP después de haber revisado cuidadosamente cómo utilizan sus datos y haber verificado que puede confIr al contenido principal iOGeminis® Géminis 🇲🇽.
